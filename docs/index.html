03 / GET IT RUNNING

Your first experiment,
without a wallet.

Clone the source, install the Python package, and open the local dashboard. The included synthetic replay needs no credentials and starts no collector.

  • Python 3.11 or later & Git
  • A modern browser
  • 8 GiB free on project & temporary drives for replay

The hosted page is a guide. The application and your research data stay on your machine.

git clone https://github.com/pigheadedpeak16/btc-lab-v3.git
cd btc-lab-v3
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -B -m btc_v3.forensics.browser_dashboard --root . --open
Then open 127.0.0.1:8592
On Windows, use your installed Python selection if it differs from py -3.11. No activation script is needed. On a fresh checkout, empty live data is expected.

06 / GOOD QUESTIONS

Before you press run.

Is this a trading bot that makes money?

No. It is a research and shadow-paper strategy tester. It does not submit real orders or establish that any strategy has a positive edge. There is no adaptive selector or funded account in this release.

Why is my Live Data tab empty?

A fresh clone includes no historical databases and starts no collection. Use the synthetic example in Strategies first. Public collectors are separate commands; complete forward-session views additionally require appropriate reference inputs and a supervised shadow workflow. See the user guide.

Can I change a strategy or create my own?

Yes. The workbench supports seven typed signal families with common and family-specific settings. Clone a preset, save immutable revisions, export definitions and archive custom strategies while retaining results. Arbitrary Python execution is not accepted through the web UI.

Does the GitHub website connect to my lab?

No. This is static documentation. Your local dashboard runs on loopback. The site has no access to your data or wallet. The screenshots and timing example are labeled synthetic or illustrative.

What happens when data is stale or unavailable?

The system reports missing inputs or rejects a decision/fill. It does not replace an old source timestamp with a recent receipt, fabricate liquidity, or count an unsupported opportunity as a loss. A retained reference can coexist with a waiting model.

What do I need for live-data research?

Available upstream services, suitable access, disk space, fresh causal observations and a verifiable host clock. Some model workflows require an authenticated read-only official reference. The demo needs none of those credentials. Live availability and long-duration behavior remain separate validation tasks.

What are the replay limits?

Browser uploads are capped at 2 MB, 5,000 events and 30 minutes. Both project and temporary drives need 8 GiB free. A report is tied to its saved definition and policy hashes. Keep incompatible execution cohorts separate.
